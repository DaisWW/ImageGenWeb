# Perf Hunt

仅在用户明确要求全项目性能扫描时使用；普通性能症状走常规工作流。
依赖、运行数据和第三方模型默认跳过。
结论必须有查询量、队列深度、延迟、分配、执行计划、图片大小、浏览器或 GPU 样本等证据。

## 范围与授权

- 根据当前及此前用户消息确定范围、约束和已有授权，不重复询问已经明确的信息。
- 用户仅要求扫描或审查时，执行只读检查并报告发现。
- 用户明确要求扫描并优化时，直接完成范围内的最小修改及受影响验证。
- 未指定数值预算不阻止不产生外部费用的本地检查；已有预算必须遵守。
- 只有缺失信息实质影响范围、正确性、真实环境、费用或明确审批操作时才询问；
  仅暂停依赖答案的步骤，继续其他已授权工作。
- 不花费额度，不触碰生产数据、真实图片、余额或密钥。

## Workflow

1. 映射序列化、SQL/锁、存储/缩略图、Worker 调度、渠道调用、前端轮询/渲染和 Docker 启动。
2. 分批检查并记录范围；优先 N+1/无界查询、重复解码、队列抖动、噪声日志、过度轮询和重复渠道工作。
3. 报告影响、置信度、证据和验证方法；不以增加副本或削弱锁、校验、重试、计费、存储安全和正确性换性能。
4. 用户已要求优化时完成最小改动并复测。
