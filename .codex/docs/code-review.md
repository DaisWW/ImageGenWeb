# 代码审查清单

触发：CR、找 Bug、质量或精简。适用 Snow AI Studio 自有源码；第三方模型和 `node_modules/` 默认不审查。

## 原则

- 从入口追到权限、状态变化、外部副作用和清理；Findings-first，只报告有触发条件、证据和影响的问题。
- 仅审查时停在建议；要求修改时做最小修复，并复查调用点、迁移、测试和完整 diff。
- 不报告纯风格偏好；无法确认时说明需要的 PostgreSQL、Docker、浏览器或上游验证。

## 精简与分层

- 只处理有证据的重复、死代码、职责混杂、隐藏副作用和不必要耦合，不以减少行数为目标。
- 保持高内聚、低耦合和单一主要职责；复杂度影响测试、修改或定位时才拆分函数/文件。
- 路由只处理 HTTP、鉴权和序列化；业务/事务在 services，外部调用在 integrations，配置从 config 读取。
- 不为单次使用增加全局状态、仓储包装或新进程；API 最小，不隐藏写副作用。
- 删除参数、重命名或收窄 API 前检查全部调用点；不用静态/全局状态掩盖参数问题。
- 一次精简只做一个主题；命名、错误和格式沿用模块风格，注释只解释原因和限制。

## 数据、文件与计费

- 服务层拥有事务提交，集成层不提交，路由不绕过服务写模型；迁移兼容干净库、旧库、空数据和回滚。
- PostgreSQL 行锁、唯一约束、配置版本和 Worker lease 必须保持；状态、预占、结算、退款和重试幂等，不能重复扣费或漏退。
- 图片先校验并安全写入，再提交元数据；失败清理文件，删除/保留期失败保留可重试元数据，不留孤立对象。
- 路径限制在受控 storage 根目录，拒绝绝对路径、目录穿越和恶意/超大图片；镜像/备份不含 `.env`、密钥、数据库、图片或模型权重。

## Worker、外部服务与权限

- 生产保持单 Web 进程和单 Worker；检查认领、心跳、恢复、shutdown、线程池和租约竞态，不能用副本解决并发。
- 上游 HTTP 有超时、状态/JSON 校验、有限重试和脱敏；不把不确定超时当成功，过期任务不能覆盖新状态。
- 每个工作站、图片、会话、任务和管理操作校验归属；前端状态不能替代权限、计费或并发校验。
- 日志只记录稳定 ID、状态、渠道和错误类别；不打印 Key、Authorization、完整提示词、图片或上游正文。

## 前端、性能、测试与输出

- 检查连点、取消、轮询、离页、长文本、响应式和部分成功；修改 JS 至少运行 `node --check`。
- 只优化有样本的热点；检查 N+1/无界查询、重复解码、队列堆积、过度轮询和多余序列化。
- 缺陷增加最窄回归用例；按受影响层运行 pytest/Ruff/compileall、迁移和 E2E 检查。
- 按 P0/P1/P2/P3 输出问题、触发条件、影响、文件/行号、证据和处理结果；报告验证及残余风险。
